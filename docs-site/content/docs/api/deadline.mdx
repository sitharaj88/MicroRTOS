---
title: EDF deadline scheduling
description: Earliest Deadline First scheduling for hard real-time tasks.
---

Earliest Deadline First (EDF) is a dynamic priority algorithm: at any
moment, the task with the **earliest absolute deadline** runs. It's
provably optimal for single-processor systems when total utilization is
≤ 100%.

EDF tasks coexist with fixed-priority tasks in MicroRTOS — opt in per
task. Enabled by `MR_USE_EDF_SCHEDULER=1`.

```c
#include "micrortos.h"
```

## `mr_deadline_job_complete`

Call at the end of each periodic iteration. Marks the current job done
and schedules the next release.

<Signature
  name="mr_deadline_job_complete"
  signature={`void mr_deadline_job_complete(void);`}
  badges={[{ label: 'Per iteration', variant: 'primary' }]}
/>

```c
void edf_task(void *arg) {
    while (1) {
        do_periodic_work();
        mr_deadline_job_complete();
    }
}
```

## Example: two periodic tasks

```c
static mr_tcb_t  fast_tcb, slow_tcb;
static uint8_t   fast_stack[192], slow_stack[192];

void init(void) {
    mr_kernel_init();
    mr_deadline_init();

    mr_task_create(&fast_tcb, "fast", fast_task, NULL, 2,
                   fast_stack, sizeof(fast_stack));
    mr_task_create(&slow_tcb, "slow", slow_task, NULL, 2,
                   slow_stack, sizeof(slow_stack));

    /* period, deadline, wcet (ms) */
    mr_deadline_task_create(&fast_tcb, 50,  40,  5);
    mr_deadline_task_create(&slow_tcb, 200, 200, 20);

    mr_kernel_start();
}
```

See [example 8](/docs/examples) for the complete program.

## When to choose EDF

Use EDF when:

- You have hard real-time deadlines that periodic-priority scheduling
  can't easily satisfy.
- Total utilization is well-bounded and you can prove schedulability.
- Tasks are periodic with known WCETs.

Stick with fixed-priority when:

- You have a mix of periodic and sporadic events with priority ordering
  that's natural (interrupt handlers > control loop > UI).
- Tasks are dynamically created and destroyed.
