---
title: Queue
description: Fixed-size message queue with blocking send and receive.
---

A queue stores a FIFO of fixed-size items in a caller-provided buffer.
Messages are **copied** in on send and out on receive — once
`mr_queue_send` returns, the kernel has its own copy, no pointer
ownership issues.

Enabled by `MR_USE_QUEUES=1` (default).

```c
#include "micrortos.h"
```

## Complete example

```c
typedef struct { uint16_t code; uint32_t value; } event_t;

static event_t       buffer[8];
static mr_queue_t    events;

void init(void) {
    mr_queue_init(&events, buffer, sizeof(event_t), 8);
}

void producer(void *arg) {
    while (1) {
        event_t e = { .code = 1, .value = mr_tick_get() };
        mr_queue_send(&events, &e, MR_WAIT_FOREVER);
        mr_task_delay(MR_MS_TO_TICKS(100));
    }
}

void consumer(void *arg) {
    event_t got;
    while (1) {
        if (mr_queue_receive(&events, &got, MR_WAIT_FOREVER) == MR_OK) {
            process(&got);
        }
    }
}
```

## Zero-copy alternative

For large messages or high-throughput pipelines, the copy on every send
is wasteful. Use [zero-copy buffers](/docs/concepts/ipc#zero-copy-buffers)
instead — you transfer ownership of a pointer.
