---
title: IPC — queues and zero-copy
description: Passing data between tasks (and ISRs) safely.
---

Two ways to move data between contexts:

- **Queues** — copy each message in and out. Simple, deterministic,
  works between any two contexts.
- **Zero-copy buffers** — transfer ownership of a buffer pointer.
  Higher throughput for large messages, more careful lifetime management.

## Message queues

A queue stores a FIFO of fixed-size items in a caller-provided buffer.

```c
typedef struct { uint16_t code; uint32_t value; } event_t;

static event_t       queue_buffer[8];
static mr_queue_t  events;

mr_queue_init(&events, queue_buffer, sizeof(event_t), 8);

/* Producer */
event_t e = { .code = 42, .value = 100 };
mr_queue_send(&events, &e, MR_WAIT_FOREVER);

/* Consumer */
event_t got;
if (mr_queue_receive(&events, &got, MR_MS_TO_TICKS(50)) == MR_OK) {
    handle(&got);
}
```

The kernel copies the bytes into the queue buffer on send and out of it
on receive. No pointer ownership issues — once you've returned from
`mr_queue_send`, the kernel has its own copy.

### Variants

| Call | Behavior |
|---|---|
| `mr_queue_send(q, item, timeout)` | Tail send, blocks if full |
| `mr_queue_send_front(q, item, timeout)` | Head send (highest-priority message) |
| `mr_queue_send_from_isr(q, item, &yield)` | ISR-safe, non-blocking |
| `mr_queue_receive(q, item, timeout)` | Head receive, blocks if empty |
| `mr_queue_receive_from_isr(q, item, &yield)` | ISR-safe, non-blocking |
| `mr_queue_peek(q, item, timeout)` | Look without removing |

When `*yield` is set after an ISR variant, request a context switch
before returning from the ISR — see your port's recipe for how.

## Zero-copy buffers

Enable with `MR_USE_ZEROCOPY=1`. The pattern:

1. Allocate a buffer from a pool: `mr_zc_buffer_alloc()`.
2. Fill it.
3. Send the **pointer** through a zero-copy queue.
4. Receiver takes ownership.
5. Receiver eventually frees with `mr_zc_buffer_unref()`.

```c
/* Setup */
static mr_mempool_t   pool;
static uint8_t          pool_memory[16 * 64];
mr_zc_pool_init(&pool, /* buf size */ 32, /* count */ 16,
                  pool_memory, sizeof(pool_memory));

static mr_zc_buffer_t *slots[8];
static mr_zc_queue_t   queue;
mr_zc_queue_init(&queue, slots, 8);

/* Producer */
mr_zc_buffer_t *buf = mr_zc_buffer_alloc(&pool, 32, MR_NO_WAIT);
if (buf) {
    memcpy(buf->data, payload, payload_len);
    mr_zc_buffer_set_length(buf, payload_len);
    mr_zc_queue_send(&queue, buf, MR_WAIT_FOREVER);
}

/* Consumer */
mr_zc_buffer_t *got = mr_zc_queue_receive(&queue, MR_WAIT_FOREVER);
if (got) {
    process(got->data, got->length);
    mr_zc_buffer_unref(got);
}
```

### Reference counting

If multiple consumers need to see the same buffer (e.g., one logs, one
forwards), use `mr_zc_buffer_ref()` before passing to the second
consumer. Each `unref` decrements. The buffer returns to the pool when
the count hits zero.

### Scatter-gather chains

For fragmented messages, link buffers into a chain:

```c
mr_zc_chain_t chain;
mr_zc_chain_init(&chain);
mr_zc_chain_append(&chain, header);
mr_zc_chain_append(&chain, body);
mr_zc_chain_append(&chain, footer);
```

The chain knows its total length so the receiver can walk it without
counting.

## When to use what

| Scenario | Use |
|---|---|
| Small structs, low rate | **Queue** — simple, no lifetime tracking |
| Large messages (>32 B), high rate | **Zero-copy** — avoid the copy |
| One bit of signal (no data) | **Semaphore** or **task notification** |
| Multiple conditions | **Event group** |

For a high-throughput logger streaming variable-length records to a
flash writer, zero-copy is a clear win. For a button-press queue
holding 8-byte events at 10 Hz, the queue is fine and simpler.
