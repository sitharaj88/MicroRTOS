A task is the kernel's unit of execution. Each task has its own stack, a
program counter, and a saved register snapshot. Switching from one task
to another is just saving one register set and restoring another.

## The TCB

`mr_tcb_t` is the per-task control block. Its layout matters because the
port assembly accesses fields by offset:

```c
struct mr_tcb {
    void              *stack_ptr;       /* offset 0 — MUST be first */
    uint8_t            priority;
    uint8_t            base_priority;
    mr_task_state_t  state;
    mr_block_reason_t block_reason;
    uint32_t           delay_ticks;
    uint32_t           wake_tick;
    mr_list_node_t   state_node;      /* ready or delayed list */
    mr_list_node_t   event_node;      /* mutex/sem/queue wait list */
    void              *stack_base;
    uint16_t           stack_size;
    void              *blocked_on;
    /* optional fields gated by MR_USE_* flags */
};
```

A TCB is **61 bytes** on AVR with default options. Disable
`MR_USE_TASK_NAMES`, `MR_USE_RUNTIME_STATS`, and
`MR_USE_TASK_NOTIFICATIONS` to drop to ~45 bytes per task.

## Creating a task

```c
static mr_tcb_t  my_tcb;
static uint8_t     my_stack[128];

mr_task_create(&my_tcb,
                 "name",        /* optional, for debugging */
                 my_func,       /* entry function */
                 NULL,          /* arg passed to entry */
                 3,             /* priority 0..MAX-1 */
                 my_stack,
                 sizeof(my_stack));
```

`mr_task_create` does five things:

1. Validates priority and stack size (`MR_MINIMAL_STACK_SIZE` minimum).
2. Zeros the TCB.
3. Fills the stack with `0xA5` for overflow detection.
4. Builds a fake interrupt frame at the top of the stack via
   `mr_port_init_task_stack` — when the scheduler does its first
   `RESTORE_CONTEXT + reti`, control jumps cleanly into your entry
   function.
5. Adds the task to the ready list at its priority.

## Sizing stacks

Start with `MR_MINIMAL_STACK_SIZE` (128 B on AVR) and measure. The
worst-case stack usage is approximately:

```
worst_case = max_local_vars
           + deepest_call_depth * 4         /* return addresses + saved regs */
           + 35                              /* fake-ISR frame from init */
           + 33                              /* one real ISR on top */
```

For typical task code that doesn't recurse and uses small locals, 128 B
is comfortable. If you call into deep libraries (printf, math, etc.), go
to 256 B.

To check actual high-water mark at runtime:

```c
uint16_t unused = mr_task_get_stack_high_water(&my_tcb);
```

This counts how many `0xA5` bytes are still untouched at the bottom of
the stack — a direct measure of slack.

## The idle task

`mr_kernel_init()` creates one task implicitly: the idle task. It runs
when nothing else is ready. By default it's a simple `while (1) { }`. You
can hook it for power management:

```c
// In your application:
void mr_idle_hook(void) {
    // Called from the idle task. Sleep, lower clock, whatever.
}
```

Enable the hook with `#define MR_USE_IDLE_HOOK 1`.

## Suspending and resuming

```c
mr_task_suspend(&my_tcb);   /* removes from ready/delayed lists */
mr_task_resume(&my_tcb);    /* puts back on ready list */
```

A suspended task is off all lists. The scheduler ignores it entirely
until you resume it.

## Yielding cooperatively

```c
mr_task_yield();
```

Drops the calling task to the end of its priority's ready list and runs
the scheduler. Same-priority tasks will round-robin; higher-priority
tasks would have preempted you already.

## Lifecycle in one diagram

```
mr_task_create
       │
       ▼
   ┌─READY──────┐
   │            │ scheduler picks
   │            ▼
   │       RUNNING ─── mr_task_delay ──► BLOCKED ── tick due
   │            │                              │
   │            └─ mr_task_yield ──► READY   │
   │                                           │
   └───────────────────────────────────────────┘

   mr_task_suspend ──► SUSPENDED ──► mr_task_resume ──► READY
```
