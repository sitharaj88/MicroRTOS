MicroRTOS is intentionally flat. Three layers, no plugin system, no virtual
dispatch unless you turn on SMP.

## Layers

```
┌────────────────────────────────────────────────────────────┐
│                      Your application                       │
│                       #include "micrortos.h"                     │
├────────────────────────────────────────────────────────────┤
│  Kernel (portable)                                          │
│  ├─ Tasks, Scheduler, Idle              src/core/           │
│  ├─ Mutex, Semaphore, Event             src/sync/           │
│  ├─ Queue, Zero-copy                    src/ipc/            │
│  ├─ Memory pools                        src/memory/         │
│  ├─ Software timers                     src/time/           │
│  └─ Diagnostics, MISRA helpers          src/diag/           │
├────────────────────────────────────────────────────────────┤
│  Port layer (one per target)                                │
│  ├─ AVR (ATmega328P, 2560, 32U4)         src/port/avr/      │
│  └─ ARM Cortex-M (SAM3X8E, SAMD21)        src/port/arm/     │
├────────────────────────────────────────────────────────────┤
│                       Hardware                              │
└────────────────────────────────────────────────────────────┘
```

## The port interface

Each port implements ~12 functions defined in `include/mr_port.h`:

```c
void     mr_port_init(void);
void     mr_port_start_scheduler(void);   // never returns
void     mr_port_yield(void);
void     mr_port_init_task_stack(mr_tcb_t *tcb,
                                    void (*entry)(void *),
                                    void *arg);

void     mr_port_enter_critical(void);
void     mr_port_exit_critical(void);
uint32_t mr_port_disable_interrupts(void);
void     mr_port_restore_interrupts(uint32_t state);
bool     mr_port_is_in_isr(void);

void     mr_port_check_stack_overflow(void);
```

A new port is about 500 lines of mostly mechanical glue. See
[Porting](/docs/porting).

## Configuration

Everything is compile-time. `include/mr_config.h` has every knob:

```c
#define MR_TICK_RATE_HZ           1000
#define MR_MAX_PRIORITIES         8
#define MR_USE_TIMESLICING        1
#define MR_USE_PREEMPTION         1
#define MR_USE_MUTEXES            1
// ...
```

Advanced features are gated by `MR_USE_*` flags. **A disabled feature
costs zero bytes** — the linker strips the unreferenced code.

| Default | Enabled |
|---|---|
| Mutex, semaphore, queue, timer, event, mempool | Yes |
| Tickless idle, EDF, MPU, SMP, tracing, zerocopy, watchdog | No |

                         │                  │

                       mr_port.h ─────────┘
                                            │

Everything resolves through `micrortos.h`. You include one header.

## Global state

The kernel holds a small amount of mutable global state, all in
`src/core/mr_kernel.c`:

| Symbol | Type | Purpose |
|---|---|---|
| `g_current_tcb` | `mr_tcb_t *` | Currently running task |
| `g_ready_list[N]` | `mr_list_t[]` | One ready queue per priority |
| `g_delayed_list` | `mr_list_t` | Tasks waiting on `task_delay` |
| `g_tick_count` | `volatile uint32_t` | Free-running tick counter |
| `g_kernel_state` | `volatile enum` | `RUNNING` / `NOT_STARTED` / `SUSPENDED` |
| `g_ready_priorities` | `uint32_t` | Bitmap — which priorities have ready tasks |

The bitmap is the key to O(1) scheduling: `__builtin_ctz` finds the
highest-priority ready task in one instruction on ARM, three on AVR.
