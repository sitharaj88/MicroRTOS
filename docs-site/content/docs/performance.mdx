Every number on this page comes from a clean release build
(`make all` with `-Os`) targeting ATmega328P, measured with
`avr-size` on the produced ELF. No synthetic benchmarks.

## Footprint at a glance

| Metric | ATmega328P (Uno) | Notes |
|---|---|---|
| Library archive | ~21 KB | Raw; linker strips what you don't use |
| Smallest example (busy-wait, ex 9) | 3,244 B flash | 384 B SRAM |
| Standard example (task_delay, ex 10) | 3,560 B flash | 464 B SRAM |
| Largest example (timer + event, ex 4) | 5,428 B flash | 1,339 B SRAM |
| TCB | 61 B | Per task, with default options |
| Idle task | ~110 B SRAM | 61 B TCB + 48 B stack default (we use 128 B) |

## Per-module breakdown

Sizes for the object files in `build/librtos.a` (release `-Os`):

| Module | Flash (text) | Notes |
|---|---|---|
| `rtos_task` | 2,280 B | Task create/delay/yield/suspend |
| `rtos_safety` | 2,688 B | Optional; safety/diag helpers |
| `rtos_queue` | 2,475 B | Message queues |
| `rtos_lockfree` | 2,311 B | SPSC/MPSC/stack |
| `rtos_event` | 1,344 B | Event groups |
| `rtos_mempool` | 1,164 B | Memory pools |
| `rtos_mutex` | 980 B | With priority inheritance |
| `rtos_timer` | 976 B | Software timers |
| `rtos_semaphore` | 972 B | Binary + counting |
| `rtos_list` | 929 B | Intrusive doubly-linked lists |
| `rtos_scheduler` | 928 B | Bitmap + ready queues |
| `rtos_port_avr` | 744 B | AVR context switch |
| `rtos_kernel` | 707 B | Globals + idle TCB + tick handler |
| `rtos_async` | 482 B | Coroutine runner |
| Stubs (EDF, MPU, SMP, WD, trace, ZC) | 0–83 B each | Empty when feature disabled |

The linker uses `-Wl,--gc-sections` and `-ffunction-sections` so any
module you don't actually call gets dropped at link time. **Disabled
features really cost zero bytes.**

## SRAM breakdown for example 4

The biggest standard example (~1.3 KB SRAM). Where does every byte go?

| Symbol | Bytes | What |
|---|---|---|
| `coordinator_stack` | 256 | App task stack |
| `worker1/2/3_stack` | 192 × 3 = 576 | App task stacks |
| `coordinator_tcb` + 3 × `workerN_tcb` | 61 × 4 = 244 | One TCB per app task |
| `g_idle_tcb` | 61 | Kernel idle TCB |
| `g_idle_stack` | 48–128 | Idle task stack (128 B recommended) |
| `g_ready_list[8]` | 48 | Priority-indexed ready queues |
| `trigger_timer`, `timeout_timer` | 27 × 2 = 54 | Two timer structs |
| `task_events` | 10 | Event group bitmap |
| `g_timer_list`, `g_delayed_list` | 6 × 2 = 12 | Kernel list heads |
| `g_tick_count`, `g_ready_priorities` | 4 + 4 = 8 | Kernel scalars |
| Other globals | ~30 | Misc |
| **Total** | **~1.3 KB** | |

**Stacks dominate.** Most apps will shrink SRAM by tuning stack sizes,
not by disabling kernel features.

## Cost of advanced features

Each `RTOS_USE_*` flag adds code only when enabled. Approximate deltas
on ATmega328P:

| Flag | Flash add | SRAM add |
|---|---:|---:|
| `RTOS_USE_EDF_SCHEDULER` | ~1.3 KB | ~50 B + per-task params |
| `RTOS_USE_WATCHDOG` | ~400 B | minimal |
| `RTOS_USE_TASK_WATCHDOG` | ~500 B | per-task state |
| `RTOS_USE_TRACING` | ~800 B | configurable buffer |
| `RTOS_USE_ZEROCOPY` | ~1 KB | pool memory you allocate |
| `RTOS_USE_MPU` | ARM only | per-task MPU regions |
| `RTOS_USE_SMP` | ARM SMP only | per-core state |

## Compared to FreeRTOS

For roughly the same feature set (scheduler + mutex + queue + timer):

| | MicroRTOS | FreeRTOS |
|---|---|---|
| Min flash (AVR `-Os`) | ~3.5 KB | ~5–8 KB |
| Min SRAM (excluding stacks) | ~250 B | ~250 B |
| TCB size (default opts) | 61 B | ~50–80 B |
| Feature gates | Per-feature `RTOS_USE_*` | FreeRTOSConfig.h |
| Hardware-validated | Yes (Uno) | Yes (many) |
| Audit surface | ~5 KLOC | ~20 KLOC |

The smaller audit surface is the real selling point for safety reviews:
you can read the entire kernel in an afternoon.

## How to shrink an app

Most-impact first:

1. **Tune stack sizes.** Use `rtos_task_get_stack_high_water` to find
   the actual usage and trim. Often saves 30–50% of SRAM.
2. **Drop `RTOS_USE_TASK_NAMES`** — save 2 B per TCB plus the string
   table.
3. **Drop `RTOS_USE_RUNTIME_STATS`** — 8 B per TCB.
4. **Drop `RTOS_USE_TASK_NOTIFICATIONS`** — 5 B per TCB.
5. **Lower `RTOS_MAX_PRIORITIES`** from 8 to 4 — save 24 B SRAM on the
   ready-list array.
6. **Disable timeslicing** if all your same-priority tasks cooperate.
7. **Disable the timer module** if you don't use software timers —
   that's the 96-byte timer task plus its stack.

## How to measure on your build

```bash
# Per-module breakdown
make all
avr-size --format=berkeley build/src/**/*.o

# Per-example breakdown
make example10
avr-objdump -d build/examples/example10.elf > example10.lst
avr-nm --print-size --size-sort -r build/examples/example10.elf | head
```

For SRAM analysis:

```bash
avr-nm --print-size -t d build/examples/example10.elf | grep -E " [BbDd] "
```
